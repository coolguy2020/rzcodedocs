# 软著项目命名规范指南

申请软件著作权时，项目名称规范对审核通过率有重要影响。本指南将帮助你为项目选择合适的名称。

## 推荐的命名结构

**品牌 + 产品用途与功能 + 结尾词**

### 推荐的结尾词

使用以下结尾词能显著提高审核通过率：

| 中文结尾词 | 英文结尾词 | 适用场景 |
|---------|---------|--------|
| 软件 | software | 通用软件产品 |
| 系统 | system | 管理或运营类系统 |
| 平台 | platform | 多功能综合平台 |
| 插件 | plugin | 扩展或增强功能 |
| 中间件 | middleware | 技术基础设施 |
| APP | app | 移动应用 |

### 命名示例

**✅ 推荐的命名：**
- 个人记账软件
- 企业财务管理系统
- 数据分析平台
- 文件转换工具软件
- 代码生成插件

**✅ 英文命名：**
- Code Documentation Software
- Project Management System
- Data Analysis Platform

## 需谨慎使用的结尾词

以下结尾词在审核时容易被要求修改，**建议避免或谨慎使用**：

| 需避免的词 | 原因 | 改进建议 |
|---------|------|--------|
| 工具 | 过于泛化，审核易被驳回 | 改为"软件"或具体功能+软件 |
| 计算器/计算 | 定义不明确 | 使用"系统"或具体应用+软件 |
| 系列 | 不够具体 | 改为具体产品名+系统/平台 |
| 助手/助理 | 功能描述不清 | 补充具体功能名称 |

**❌ 不推荐的命名：**
- 记账工具
- 代码生成计算器
- 文件处理系列
- 智能助手

**✅ 改进后的命名：**
- 个人记账管理软件
- 代码生成系统
- 文件格式转换平台
- 文档智能生成软件

## 最佳实践

### 1. 名称需要包含版本号
- 推荐：项目名称 + V/版本号
- 示例：`个人记账软件V1.0`、`财务系统2.1`

### 2. 避免过于宽泛
- ❌ "管理软件" → ✅ "企业人力资源管理软件"
- ❌ "数据工具" → ✅ "数据分析与转换系统"

### 3. 中英文混用需注意
- 可以混用（如 `数据转换Pro`），但要确保整体规范
- 建议保持主体中文，辅助信息可英文

### 4. 避免特殊字符
- 尽量使用常见汉字和英文字母
- 避免过多符号或非规范标点

## 申请流程建议

1. **项目命名阶段**：在软宝宝创建项目时，按本指南选择合规的名称
2. **提交准备**：再次检查名称是否符合本指南规范
3. **审核阶段**：如收到驳回通知，参考本指南调整项目名称

## 常见问题

### Q: 可以用纯英文命名吗？
A: 可以，但建议用中英结合，中文为主。纯英文也可以通过，但中文更符合国内软著审核习惯。

### Q: 已有项目名称不符合规范，还能改吗？
A: 可以。在申请前修改项目名称通常不会有问题。已申请的项目如被驳回，可根据审核意见修改后重新提交。

### Q: 名称要多长？
A: 建议 4-20 个中文字符（或等量英文），过短显得不专业，过长显得冗余。

### Q: 竞品软件同名怎么办？
A: 可以在基础名称上区分版本或功能，如 `XXX软件Pro版` 或 `XXX专业版系统`。
